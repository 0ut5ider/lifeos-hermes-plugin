# LifeOS hook parity resolution plan

Date: 2026-09-28. Target: the pinned public LifeOS installation and Claude Code 2.1.272, compared with the isolated Hermes installation on `.212`. Hermes hardline, user-deny, guardian, and Tirith denials remain authoritative. Haiku, Sonnet, Opus, and Fable may share one private model with configurable effort levels. SSH and Docker project hooks remain opt-in. These decisions define intentional differences; they do not exempt a behavior from testing.

The current registration inventory is 74 hooks across 11 Claude Code events. A registered callback, a passing unit test, or a plausible translation is not proof that its observable effect matches Claude Code. Every claim below needs a control run in Claude Code and a Hermes run under matching settings, or a documented reason why the control is unavailable. Keep the model prompt and fixture deterministic where possible; judge hook events and side effects rather than the model's prose.

## Immediate work order

1. Capture the current registration inventory and make missing or changed registrations fail a check.
2. Run native probes for `PreToolUse` ask and SessionStart and SessionEnd matchers. Reproduce the current Hermes outcomes with real child hooks.
3. Implement the smallest bridge changes that satisfy those probes. Keep Hermes denial precedence and approval identity stable.
4. Run the malformed-policy decision through the installed gateway. Add a regression if source and gateway behavior differ.
5. Expand the paired permission and lifecycle matrix from observed differences. Fix confirmed gaps in the test fork, then run the complete suite and live SSH/Docker cases before one staged release.
6. Perform the clean install and update rehearsal. Record the tested compatibility set and ask for independent review of the evidence before claiming parity.

The completion gate is a status for every item in the agreed contract, no unresolved mismatch or unverified item within the claimed local, SSH, and Docker scope, and a tested clean installation and update path. Generic Hermes changes can be proposed upstream in parallel. Acceptance upstream is not a substitute for the installed behavioral checks.
