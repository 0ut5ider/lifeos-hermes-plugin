# LifeOS hook parity record

This record describes the public LifeOS hook settings installed from commit `5e2f2e8` on 2026-09-27. It distinguishes registered callbacks from verified behavior. The bridge is a Hermes plugin. It does not edit LifeOS source files.

## Event coverage

| Claude Code event | Registrations | Hermes path | Current result |
| --- | ---: | --- | --- |
| `PreToolUse` | 6 | `pre_tool_call` | Command and local HTTP hooks execute for mapped and unmapped Hermes tools. Exit code 2 and deny decisions block. Updated input maps back to Hermes arguments. An outer `execute_code` also presents its Python source as a Bash command to named Bash guard groups. |
| `PostToolUse` | 32 | `augment_tool_result` | Hooks execute after the existing result transform. Their `additionalContext` and exit-2 stderr are appended to the model-bound result. Plain exit-0 stdout stays out of model context. Content-bearing Hermes browser results also reach `WebFetch` matchers while generic hooks keep the Hermes tool name. |
| `UserPromptSubmit` | 9 | `pre_llm_call` | Hooks execute before the current prompt enters the bridge transcript. A block prevents model processing and discards the current prompt from bridge and Hermes history. For multimodal content, the hook receives the text portions joined with newlines. Allowed hook context is added to the current user turn. Async hooks start without blocking. |
| `Stop` | 8 | `pre_turn_stop` | Hooks execute on each text answer. A block withholds the candidate from Hermes user delivery and session history, then continues the same turn up to eight times by default. At the continuation limit, the default allows the answer as Claude Code does; the plugin's `fail_closed` setting instead returns an incomplete result. Iteration-budget exhaustion also returns an incomplete result. `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` overrides the continuation limit. The native hook sees the prior transcript and the current answer in `last_assistant_message`; the bridge appends the current answer after the hook. A private transcript supplies `transcript_path`. |

| `PermissionRequest` | 2 | `pre_command_approval` for Bash and `pre_tool_call` for files and MCP | Native `Safety.hook.ts` runs for guarded Bash commands that may need permission; simple probed `pwd` and unquoted `echo` forms skip this event unless a matching or unsupported deny or ask rule requires review. Literal Bash rules from local user, trusted project, and file-based managed settings apply in deny, ask, allow order. A native allow cannot bypass a matching ask rule; an unreadable managed file keeps the command on the review path. | `ConfigChange` | 1 | bridge file watcher while a session is active | Installed user, project, local, and file-based managed settings plus user and project skills are checked once a second. | `StopFailure` | 1 | `api_request_error` plus `on_turn_result` | Terminal API errors run the native log hook once with the last API error. Direct error returns and exhausted retries are covered. An earlier recovered API error does not turn an unrelated local failure into StopFailure. |

The native bridge executes the installed registration types with partial coverage of `ConfigChange` and Bash `PermissionRequest`. Literal local Bash rules are tested against Claude Code 2.1.272; parser-backed compound Bash rules, wildcard allows, and documented wrappers are supported for tested forms. Redirects to `/dev/null` or file descriptors and here-docs have no file target and can use a matching Bash allow. Literal redirect and `tee` file targets check `Read` and `Edit` deny and ask rules before a native Bash hook grant. Literal file operands of `cat`, `head`, `tail`, and `sed` are also checked, including forms reached through recognized Bash wrappers. `sed` scripts stay on the review path because they can open additional files. The bridge uses settings-source anchors and gitignore-style path patterns for those targets. Dynamic targets, other file-opening Bash commands, remote symlink destinations, uncommon shell forms, and non-file managed sources remain incomplete. See [the redirect file-rule probe](../notes/2026-09-28-redirect-file-permission-gap.md) and [the reader operand probe](../notes/2026-09-28-reader-file-permission-gap.md). Trusted SSH and Docker project Bash deny rules passed live isolated workspace tests. The Docker probe also verified a compound deny and a remote skill-file digest. The bridge reads local managed JSON files before each Bash decision, including drop-ins; a matching deny blocks despite a user allow. The file-based `allowManagedPermissionRulesOnly` lock excludes user and project Bash rules when enabled. Hermes safety denials still apply after this bridge decision. See [the permission rule probe](../notes/2026-09-28-bash-permission-rules.md). The MCP `PermissionRequest` registration executes, but Hermes's trusted-server policy can still differ from Claude Code's permission rules. Direct Read, Write, and Edit calls now apply literal `Read` and `Edit` deny rules before a native hook grant. Matching ask rules request human review even after a hook grant. A multi-file patch checks every target, while Hermes file guards and approval scope can still differ from Claude Code. For new Hermes todo IDs and kanban task calls, the patched native `TaskCreated` hook now runs with session-owned counts. The bridge retains a policy fallback for unpatched LifeOS installs. This is an event-level mapping, not a count of passing behavioral tests. Hermes tool names currently mapped are `terminal`, `read_file`, `write_file`, `patch`, `clarify`, `delegate_task`, `web_search`, `web_fetch`, `web_extract`, `skill_view`, and `tool_search`. The bridge keeps every other Hermes tool name, including `mcp__*`, so generic hooks and the transcript see it. `web_extract` maps to `WebFetch` so the native Safety hook can inspect fetched page content. Content-bearing browser tools reach `WebFetch` PostToolUse matchers without changing their name for generic hooks or the transcript. An outer `execute_code` script reaches named Bash PreToolUse groups with its Python source as `command`; generic hooks still see `execute_code`. Bash command rewrites do not change Python source. Hermes `clarify` maps to Claude Code `AskUserQuestion` for the installed tab-state hooks. Claude Code `MultiEdit` has no exact Hermes tool mapping. Batched Hermes delegation now runs the `Agent` hooks per child with a description, prompt context, background state, and explicit model when supplied; Hermes has no matching Claude subagent type, so the bridge labels each child `general-purpose`. Local Pulse routes fail open when Pulse is not running, as they do in Claude Code. Project hook registrations load only from roots in Hermes's `skills.trusted_project_dirs`. User, project, and local hook groups run in that order for the matching project session.
