## Remaining finding: Responses string input is omitted from compression filtering

Severity: Medium for the bounded admission callback, with full host-path reachability unverified.

_messages deliberately skips a string input, which is appropriate when the string is an ordinary primary user request. The new compression branch also obtains all generated input exclusively from _messages. Consequently, the string form is never checked even when trusted aux_task='compression' identifies generated content.

The real probe:

1. Saves and forgets a synthetic principal claim.
2. Loads that claim from stale SOUL through the actual host loader.
3. Refreshes the on-disk SOUL before fresh admission, matching the original cached-prompt reproduction.
4. Uses an explicitly approved Responses route.
5. Invokes the actual required host middleware with aux_task='compression' and calls OpenAI.responses.create with input equal to the cached string.

The local server captures one request to /v1/responses with the retired cached SOUL claim in input. Admission returns normally. The SDK receives a response without an exception.

Evidence: raw/probe_responses.py, raw/responses-child.py, and raw/responses-result.txt. The capture records requests=1 and retired_claim_on_wire=true. The fixture response uses the existing simple local response shape; this reproduction relies on the captured outgoing request, not any claim about real Responses model output.

Recommended correction: include plain string input in the generated compression scan, or reject that representation when aux_task is compression. Keep the ordinary primary-user quote exception. Add a negative string-input case and a clean string-input control. The current actual host adapter uses list input, so no claim is made that the stock adapter presently exercises this form.
