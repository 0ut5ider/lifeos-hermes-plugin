# Native installation counts

Date: 2026-10-05. This candidate unit admits the native `GetCounts.ts` inventory under current unrestricted owner read authority. It changes no deployed server, ownership, sharing, or job setting.

The service fixes the installation root, LifeOS data root, and optional count key. It uses the original native calculations for skills, workflows, hooks, signals, files, work, research, and ratings. JSON, shell variables, and all eight single-count formats match the pinned original program. A read-only owner can request counts. Unbound, revoked, restricted, foreign-root, and missing-connector calls refuse without count output.

Counts describe physical file and row inventory. They do not describe active facts or return source text, filenames, or record references. The original program counts nonempty ratings rows without parsing them. It also retains its existing behavior for missing or unreadable directories. Two identical native collections reject a changed numeric inventory. They do not prove unchanged file contents or detect an inventory that changes and then returns to its earlier count.

The corrected baseline passes native format comparisons but fails four missing-authority and foreign-root controls. The first candidate passes five tests and ten subtests. Expanded controls expose two path defects: a redirected research directory remains countable, and an unrelated single-count request checks a redirected ratings file. The corrected service checks only the selected data paths before collection and before the second native collection.

Additional controls cover owner read permission without write permission, durable managed markers after connector loss, fixed root aliases, invalid source arguments, and actual authority or inventory edits after native collection. The interleaving controls run the real native worker and change real configuration or ratings files. They do not replace the worker result.

The final fresh distributed gate passes **88 tests and 81 subtests in 122.40 seconds**, with no failures, errors, or skips. It covers counts, native records, delegation, source admission, registry aliases, ratings, packaged patch equality, and preparation from pinned sources. `final-command.json` records the command, environment, source manifest, test and product hashes, and dependency origin. `final-output.txt` and `final.done` record completion. Twelve synthetic outcomes remain in `final-outcomes`.

`source-comparison.json` confirms that all 56 native patch files equal the prepared scratch source and all 19 root/runtime patch pairs match. This unit adds `GetCounts.ts` to the existing memory patch. It changes no dependency or patch group. Complete caller policy coverage and the remaining ownership and release checks still block activation.
