## Measured corrections

The bridge now records the served carrier before the Hermes transcript write.
Explicit tier selection remains unchanged. It normalizes batched questions and
records the synchronous fallback when the host cannot deliver a background task.

The native configuration logger now uses `file_path` and keeps a separate baseline
for each source. The first observation remains an initial snapshot. Later edits
produce a difference against that source, rather than against user settings.
Skill audit rows use a content digest and do not copy the complete skill text.

Hermes previously classified a successful extracted page with `error: null` as a
failure. That classification skipped the successful-result Safety callback. The
new result classifier uses structured error values and successful page content.
A partially successful result retains the Safety callback for successful pages.

## Limits

The question fixture uses the real native interactive CLI and a Hermes AIAgent
host with explicit session finalization. It tests queue and terminal-state files;
it does not test a desktop window or Discord prompt and reply delivery. Discord
remains on `.212`. Its migration to the new gateway and the actual adapter round
trip remain combined-release acceptance work.

The web provider serves a real local HTTP corpus through the pinned document
provider interface. The fixture permits its private loopback URL only in the
isolated environment. These four inputs do not prove detection of every possible
prompt injection.

The batch fixture applies a real six-file patch. Its partial case uses an actual
filesystem permission denial on the second file. Hermes runs observers for the
first applied file and suppresses the checkpoint for the incomplete batch. The
native comparison invokes handlers with MultiEdit-shaped data. It intentionally
omits the checkpoint for a failed batch under the functional contract. It does
not assert native CLI partial-batch behavior. The evaluation case preserves an
existing debounce marker; other evaluation branches remain separately tracked.

These changes remain staged on the feature branch. The production gateway,
Discord configuration, memory ownership, and selected model tier mapping remain
unchanged until combined release acceptance.
