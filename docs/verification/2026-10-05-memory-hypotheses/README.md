# Governed native hypothesis derivation

Date: 2026-10-05. Role: primary implementation and verification.

Managed hypothesis derivation consumes admitted native ratings, recurrence sources, Wisdom frames, current hypotheses, state, logs, and principal identity. The service checks current unrestricted owner recall and the fixed installed sources. It keeps the native candidate thresholds, scoring, deduplication, privacy suppression, note formatting, updates, expiry moves, and daily-run decisions for the authorized fixtures.

Managed dry run returns native counts without creating a directory, state, stamp, or log. This is a deliberate policy change from the original dry run, which appends a log. Writing requires unrestricted owner write access. The operation journal publishes notes, archive moves, state, logs, and the optional daily stamp as one recoverable operation. Files use mode 0600. Source, authority, and destination changes refuse publication and preserve later edits.

## Limits

The public install omits test/lib/hook-replay.ts. Native default derivation therefore skips healing fixture proposals. The managed renderer retains the tested missing-harness behavior and refuses a present harness until its complete fixture publication path has governed admission. These results do not establish actual healing inference or fixture execution.

Registered hypothesis sources require explicit review before regeneration changes them. The service preserves those facts rather than silently remove or move their references. Existing excluded hypothesis state or logs also refuse derivation. The source limit is 256 KiB, the corpus limit is 3 MiB, and directory and publication discovery remain bounded. This gate does not establish every malformed input or every existing archive collision.

The public native tools package has no typecheck, lint, test, or build script. Actual Bun calls exercise the tested paths. These fixtures do not prove live private model judgment, scheduled authority, restricted prompt delivery, aggregate ownership recovery, the complete caller inventory, or memory activation. No production server, configuration, ownership, or sharing setting changes. The combined release gate remains open.
