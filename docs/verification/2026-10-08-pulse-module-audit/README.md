# Selected Pulse module audit

The audit uses the prepared Atlas candidate and the actual native daily profile merger. The profile enables 23 optional module switches. It also retains the always-loaded infrastructure modules. Thirty native module imports appear in the public Pulse program.

The inventory records public route and source lines and their hashes. A governed API reference does not prove complete route coverage. Absence of that reference does not prove an unsafe route. The inventory supplies the required route classification worklist.

The actual synthetic HTTP probe makes eight anonymous requests to five native modules. All eight return HTTP 200 without a no-store header. The Books, Projects, Assets, and Evals data responses contain synthetic personal labels. The Books source includes an explicit private marker. Ambient owner and internal flags do not provide authenticated HTTP authority.

The probe starts actual native handlers on a disposable localhost listener. The owner configuration has the managed HTTP marker. The probe makes no model request and reads no installed personal record. It explicitly binds each native path override to the disposable home. The source profile, source-route inventory, response JSON, program, and empty error output remain reviewable artifacts.

Books, Projects, Assets, and Evals require current owner admission. ThreatModel requires source classification and route admission even when its fresh source is malformed or absent. Other active modules remain unverified by this selected probe. The static manual caller count does not represent the complete remaining coverage.

The Atlas combined run does not close these separate module gaps. Installed release acceptance and daily deployment remain open.
