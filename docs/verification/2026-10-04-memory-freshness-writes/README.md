# Native freshness timestamp and cache publication

Date: 2026-10-04. This evidence covers native timestamp mutations and the constitutional freshness cache. It uses synthetic owner sources and actual native functions. Production remains unchanged.

The first [timestamp baseline](before.txt) reports 21 failures, nine passed parent tests, and four passed subtests. The [cache baseline](cache-before.txt) reports five failed tests and four passed tests. The native writer accepts read-only callers, creates a publication directory before authorization, writes public file permissions, follows a foreign cache directory, and permits a registry alias.

The bridge now supplies admitted current source text to the original timestamp transformations. It checks owner write authority, the fixed target, source signatures, generated metadata, and current configuration before journaled publication. Native write and review clocks keep their separate meanings. Managed default writer labels use the authenticated writer. Standalone LifeOS keeps its original default identity lookup.

The cache uses the original payload builder with admitted current source bytes and native file times. Its publication journal covers `LIFEOS/USER/CACHE/freshness.json`. A read-only owner can print the current payload without creating the cache directory. Missing context, revocation, redirected destinations, and registry aliases refuse publication. Atomic publication uses private owner permissions.

The first [interleaving control](interleaving-before-output.txt) reports one failed test, two passed tests, and four passed subtests. A source edit after native rendering survives the initial refusal, but recovery removes that edit. The timestamp input is also its publication target. Source-signature conflicts now commit a conflict receipt before publication, so recovery preserves the later source. [Corrected controls](interleaving-candidate-output.txt) pass all three tests and four subtests. Actual process death after publication still restores the previous source.

The [expanded gate](expanded-output.txt) passes 37 tests and 34 subtests. It covers actual process exit after publication for the user timestamp file, all three fixed system files, an existing cache, and the first cache. It verifies exact old-source review, missing and empty sources, single-line metadata labels, retired text in generated metadata, native body transformations, read-only printing, private permissions, and durable managed markers.

The [final recorded controls](final-controls-output.txt) retain 38 passing native cases with actual commands, console output, synthetic source snapshots, and cache artifacts. The earlier [controls](controls-output.txt) retain the 37 cases before the excluded-edit correction. The [distributed comparison](distributed-comparison.json) verifies all 37 native files against the scratch source. Both patch copies are equal. Dependency directories copy unchanged, previously frozen dependencies. The two [Bun builds](build-results.json) pass. Bundling does not validate TypeScript types.

The [broader candidate gate](final-output.txt) passes 350 tests and 233 subtests without failures, errors, skips, or warnings. It predates the later excluded-edit regression. The [failing probe](excluded-source-before.json) adds private markup after actual native rendering. Admission refuses the changed source before the signature comparison, so recovery still restores the old source. The [corrected probe](excluded-source-after.json) preserves the later excluded edit. Pre-publication source admission refusals now commit a conflict receipt as well.

The [final correction gate](exclusion-final-output.txt) passes 90 tests and 60 subtests without failures, errors, skips, or warnings. It includes the new actual-process regression, all timestamp and cache cases, freshness readers, post-render reader changes, service operations, exact source review, and registry-alias controls. The two gates have separate commands and source hashes. No test-imported source changes while either gate runs. The broader gate is not rerun after this focused exception correction.

This unit does not complete Interview and migration callers, other derivative publishers, aggregate service recovery, restricted delivery, ownership activation, or the combined release. It does not protect against a hostile same-UID process replacing a destination between the last filesystem check and atomic publication. The existing cooperative writer and recovery contract remains the supported boundary.
