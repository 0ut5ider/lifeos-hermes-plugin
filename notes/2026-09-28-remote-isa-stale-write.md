# Remote ISA stale write reproduced on isolated SSH backend

On 2026-09-28, I created a disposable SSH account on `.212` and selected Hermes's SSH terminal backend in a temporary profile. A real `read_file_tool("ISA.md")` returned two lines from `/home/lifeosparityprobe/workspace/ISA.md`. A second SSH command changed the second line from `old` to `external edit`. A real `write_file_tool("ISA.md", ...)` then returned no `stale_write_blocked` flag or error and replaced the remote file with the stale `old` line plus `my edit`.

The native LifeOS ISAStaleWriteGuard reads `tool_input.file_path` with a local filesystem API. The SSH target path does not exist on the Hermes host, so its documented fail-open branch cannot protect this file. Hermes's own stale-write guard also calls local `os.path.getmtime` and `Path.exists` on the remote path. This probe confirms the combined behavior, not just the source-level risk. The remote account, key, and synthetic profile are temporary and contain no production data.

The first live regression assertion failed as expected: `stale_write_blocked` was absent. The Hermes fork now asks the active backend for a SHA-256 digest on both sides of a Read and immediately before a Write. A full unredacted read, or complete pages of the same digest, establishes that task's baseline. A missing remote file can be created; an existing file with no matching baseline is refused. An unavailable digest fails closed. A successful write establishes the next baseline only if the backend's digest matches the bytes Hermes wrote. The baseline key includes the backend session and target path.

After the change, the live SSH regression passed. It preserved the external edit, allowed a merged write after a fresh read, refused an unread existing file, allowed creation, accepted three paged reads, and detected another external edit after its modification time was restored. The isolated fork commit is `aa0b6e5c8`. The patch passed `git apply --check` on the public Hermes source after the hook-controls patch. Hermes's canonical runner passed 159 focused file tests with zero failures and eight fixture or platform skips; the live SSH regression passed separately. The native LifeOS ISAStaleWriteGuard still cannot read a remote file path on the Hermes host, so the core guard supplies the effective stale-write refusal but does not make that native hook remote-aware.

The disposable SSH account, its key, and the temporary probe script were removed after testing. The isolated Hermes dashboard restarted from the patched source and returned HTTP 200 at its LAN status endpoint. Production `.211` and `.213` were not changed.
