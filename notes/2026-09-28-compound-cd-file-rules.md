# File rules after a Bash directory change

Date: 2026-09-28. An independent Astra review found that the bridge checked `cat secret` against the original working directory after `cd sub && cat secret`. In a disposable local fixture with `Bash(*)` allowed and `Read(//.../sub/secret)` denied, `cat sub/secret` returned deny, while `cd sub && cat secret` returned no restriction. The same bypass appeared with a subshell and a semicolon. The command parser reported `secret` as certain but did not carry the `cd` directory into its target path.

Claude Code 2.1.272 ran a paired probe in the isolated `.212` reference account through its private local model. The exact command was `cd parity-cd-a9z314ib && cat secret`. Its control had zero permission denials and returned the synthetic marker. With a matching absolute Read deny, JSON output reported one Bash permission denial, and its `tool_input.command` was unchanged. The disposable directory was removed after the probe. The summarized native data and the Astra bridge fixture are in [the review artifacts](../docs/agents/2026-09-28-parity-fresh-review/parity-fresh-review.md).

The bridge now carries a literal `cd` path through following commands and resolves each literal file target in that directory. A subshell restores the outer directory. A pipeline does not carry one segment's directory into another. Dynamic destinations, `cd -`, conditional directory changes, and wrapped directory changes stay on the review path when the parser cannot establish a single target directory. A semicolon after `cd` also requests review if the directory change may fail, while a matching Read deny still blocks the path reached when it succeeds. This checks permission before execution and does not claim to emulate every Bash control flow form.

The local and `.212` source suites passed 279 tests, with 66 and 55 optional skips respectively. Focused live SSH and Docker tests denied a symlinked file reached through `cd sub && cat link.txt`. The Docker test removed its container and temporary socket access entry. Other remote backend types were not exercised.
