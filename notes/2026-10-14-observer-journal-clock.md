# Observer journal clock

The actual automatic evening job starts at 18:02:53.006 and completes at 18:03:19.076 Toronto. The Pulse state stores lastRun=1792015399076 milliseconds. Journald records the completion at 1792015399076475 microseconds. The installed observer demands that state time follow the journal time, so a 475-microsecond capture delay rejects a successful execution. The native producer emits its own millisecond ts before storing state. Its asynchronous journal capture uses a different timestamp.

The failure is reproducible from the recorded events. A new regression using the measured 212-microsecond start and 475-microsecond completion delays fails before the fix. The staged validator correlates state with the native event clock and separately bounds journal capture delay to five seconds. It rejects missing, naive, reversed, and excessive event/capture timestamps, as well as stale state. All 12 observer tests pass. The original installed failure remains preserved. No installed plugin or native program file changes.

A read-only replay uses the staged validator against the original cron journal window. It also uses the unchanged installed Discord window checker. That checker scans all 58 messages and finds exactly one Cerebo delivery at 18:03:17.821. No job or Discord send is repeated. The regular schedule and original configuration bytes are restored.
