# PermissionRequest updated input

Date: 2026-09-28. Claude Code 2.1.272 was tested in the isolated `.212` reference account with a disposable Bash PermissionRequest hook. An allow-only control executed the original `printf ORIGINAL > file; printf DONE` command. With `decision.updatedInput.command` set to `pwd` and only the disposable settings source loaded, the original file was absent, there were zero permission denials, and a PostToolUse hook received `tool_input.command: pwd` with `pwd` output. This proves the pinned reference can replace a command at PermissionRequest. The [control](../docs/agents/2026-09-28-native-contract-probe/permission-allow-control.jsonl) and [rewrite result](../docs/agents/2026-09-28-native-contract-probe/permission-rewrite-pwd-post.jsonl) record the comparison.

An earlier probe with the account's default LifeOS permission hooks present executed the original command despite the disposable rewrite hook running. The first isolated rewrite to another file command produced a permission denial and no file. A rewritten command is subject to later permission checks; the measured `pwd` case avoids a second prompt. The probe scripts used disposable files and removed them afterward.

The bridge currently reads `decision.behavior` from PermissionRequest but drops `decision.updatedInput`. Its Bash command-policy host callback returns only allow, review, or deny, so it cannot replace the command at that stage. The Hermes host needs a generic command replacement contract that rechecks the replacement under its safety and permission rules. Direct file and MCP PermissionRequest rewrites need separate native probes and bridge mapping. No rewrite support is claimed yet.
