# PermissionRequest input replacements

Date: 2026-09-28. Target: Claude Code 2.1.272 in the isolated `.212` reference account and the `.212` Hermes test install. [Claude's hook reference](https://code.claude.com/docs/en/hooks) says `PermissionRequest.decision.updatedInput` replaces the whole tool input and is checked again against deny and ask rules. The pinned native runs below measured the behavior, rather than relying on the current reference alone.

The Bash control wrote the original command's file. A Bash hook that replaced the compound command with `pwd` executed `pwd` and did not write the original file. The native PostToolUse input named `pwd`. The Hermes bridge now returns a replacement from `pre_command_approval`. The generic Hermes host patch rechecks that command with pre-execution guards and command approval, then runs the final command. A disposable run through the installed plugin manager executed `pwd`; its original file was absent. The focused host suite covers denial precedence, hardline blocks, malformed replacements, cycles, foreground and background dispatch, and the outer PostToolUse arguments. Mixed review and rewrite decisions fail closed because a review of the original command does not authorize the replacement. The installed host files were backed up with `.before-command-rewrite-20260928` and `.before-command-audit-20260928` suffixes.

For Write, the first probe used a path under `.claude`. A hook grant with changed input was denied on reevaluation, including when only the content changed. Moving the disposable workspace to an ordinary directory changed the result: the native PostToolUse input named the replacement file and content, the original file was absent, and the replacement file contained the requested content. The bridge now maps a direct Write or Edit replacement to Hermes arguments and checks the final target against LifeOS file rules. The installed-plugin probe wrote only the replacement and blocked a second run when the final path had an `Edit` deny rule. A multi-file Hermes patch replacement currently blocks because it cannot map one native replacement to multiple patch operations without changing the patch itself.

For MCP, an explicit ask rule for the whole tool caused native reevaluation to deny the rewritten call. Without that ask rule, the native stdio server received `MODIFIED`, and PostToolUse saw `MODIFIED` instead of the requested `ORIGINAL`. The bridge now returns modified MCP arguments. A disposable real Hermes MCP server received `MODIFIED` through the installed plugin manager. The server exercised one local stdio tool and did not prove every Hermes trusted-server policy or other plugins' decisions against the final arguments.

Raw native results are in `docs/agents/2026-09-28-native-contract-probe/` under `permission-rewrite-*.jsonl`, `file-*.jsonl`, and `mcp-*.jsonl`. The installed Hermes outcomes are `command-rewrite-hermes.json`, `file-rewrite-hermes.json`, and `mcp-rewrite-hermes.json` in the same directory. The probe scripts are adjacent to those results or in `scripts/`. All files created for native and installed probes were disposable. The ordinary file workspace corrected a real fixture error: `.claude` is a protected target, so the earlier file denials did not establish that Write replacement was unsupported.

An independent implementation review found two missed command cases: a `review` result hid a separate replacement, and argument coercion left the outer Hermes PostToolUse observer with the original command. Both now have regressions and pass in the `.212` host source. The focused host suite passed 40 tests; 216 approval and terminal tests passed in a wider run. Four gateway approval-batch cases timed out, but the same four failed at the unmodified base revision in a separate worktree. This is a baseline test failure, not evidence that the command patch passes that approval path. The `.212` gateway runs the changed files, with `model_tools.py`, `approval.py`, and `terminal_tool.py` backed up before replacement.
