# Claude carrier probe on the Hermes test install

Date: 2026-09-28. The installed LifeOS `CarrierProbe.ts --check` on `.212` exited 1 with `CarrierProbe: NEVER RUN`. `IntegrityCheck.ts` invokes this check and records a blocking `carrier-probe` finding when it fails. This is an active LifeOS integrity gap, not merely a missing optional test.

The native probe starts a Claude Code Haiku session, requests an Agent dispatch with `model: fable`, then reads Claude Code subagent transcript files. It compares the executed model name to `DISPATCH_EXECUTES_FABLE` in LifeOS `models.ts`. The Hermes installation instead maps Fable to a configurable Hermes provider, model, and effort. Its ordinary LifeOS child launcher performs direct inference, so running the Claude-specific probe through that launcher would not establish Hermes delegation behavior. Writing a successful state file without observing a real child request would hide the gap.

A separate clean-account probe demonstrated that a real Hermes delegated Agent used the selected beta provider and model. It failed without a chat request to alpha when beta returned HTTP 503. That probe did not produce the persistent freshness evidence that LifeOS IntegrityCheck expects.

The bridge now includes `carrier_probe.py`. Its `--run` command creates a real Hermes child for the current Fable provider, model, and effort. It records a successful API call and completion in a private state file. Its `--check` command rejects missing evidence, failed runs, route changes, and results older than 30 days. Starting a new probe first invalidates an earlier success, so a failed rerun cannot leave a false green result. Its `--check-main-rung` command compares the configured Hermes main-loop route with the LifeOS top tier. The LifeOS compatibility patch makes IntegrityCheck use these commands only when the bridge sets `LIFEOS_HERMES_CARRIER_PROBE`; Claude Code keeps its native probe.

On the `.212` test account, the child completed one API call using `custom / flashnext-w4a16-fp8ple / xhigh` and returned `OK`. A changed Fable effort produced `ROUTE CHANGED`. Before the Hermes main effort changed from medium to xhigh, the rung check produced `MAIN EFFORT MISMATCH`; after the change, both IntegrityCheck sections passed. The child result reports Hermes's requested provider and model. It does not independently attest to the model that the private server loaded internally. Other IntegrityCheck sections still report 156 blocking content findings in this fresh LifeOS fixture.
