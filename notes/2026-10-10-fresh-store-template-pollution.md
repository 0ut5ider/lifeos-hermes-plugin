# Fresh-store examples entered personal output

Date: 2026-10-10. Question: Does a named fresh LifeOS store contain only empty personal sections?

The earlier installed morning brief contained three shipped sample goals. The samples did not come from a test conversation. `FreshStore.prepare` copied the complete native USER tree and checked that its bytes matched the upstream templates. It checked zero active memory facts, but templates remained available as personal source files. The native brief parsed their `G0`, `G1`, and `G2` rows as active goals.

The first failing test proves that sample goals survive preparation. A second test exposes structured examples after Markdown sections become empty. The shipped Finance YAML contains 18 vendors and 10 obligations. Removing Markdown examples alone leaves those financial records active.

The fix runs only during preparation of a new store. It preserves native headings and template metadata, retains exact originals outside the active USER tree, empties both financial lists, and omits three example company and customer directories. It does not filter words such as `sample` from existing personal data. It does not change native renderers or add patches.

The installed result has zero active facts, 54 empty personal template files, and three omitted example files. Actual native Finance, Health, Business, Work, and morning rendering pass. The morning output becomes `Good morning.` The separate store remains unselected, with ownership, sharing, and services disabled. The source profile bytes remain unchanged.

The record and both failing checks are in [daily release evidence](../docs/verification/2026-10-10-daily-text-release/). The comparison shows why zero indexed facts alone is insufficient to establish a fresh personal store.
