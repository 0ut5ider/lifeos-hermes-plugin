# Live Discord delegation exposed a missing watchdog

On 2026-09-28, Adrian sent a test request to the separate `.212` Discord bot. Hermes stored a top-level `delegate_task` call without a `background` argument. Its tool result reported `status: dispatched` and `mode: background`. The child ran `sleep 120` and completed with `WATCHDOG-212-DONE`. The native AgentInvocation hook logged `subagent_start` and `subagent_spawned_async`. No `AgentWatchdog.ts` process or watchdog state file appeared during the wait, and no alert appeared in Discord.

Hermes's `run_agent.py::_dispatch_delegate_task` always dispatches a top-level model-facing child in the background and runs a child agent's own delegation inline. The bridge's `_agent_inputs` previously computed `run_in_background` from `bool(args.get("background"))`. The model-facing arguments omitted that field, so the bridge told LifeOS Pulse that the actual background child was foreground. Pulse therefore did not request a watchdog.

The new bridge default uses Hermes's delegated-child context when the argument omits `background`. An explicit Boolean argument still takes priority for direct callers. The regression test failed before the change and passed after it. The full plugin suite passed on `.212`: 172 tests, 45 optional skips. The updated plugin file was installed on `.212`, and the gateway restarted after the first child completed.

Adrian sent a second request at 09:12 Eastern. This time the native watchdog started. The child transcript for `deleg_132cba94` showed a `process_manage wait` call at 09:13:06 and its result at 09:15:05, with no tool result between them. No watchdog alert appeared in the Discord thread. The bridge had mirrored Hermes's `seconds_since_progress` into LifeOS's tool activity file. Hermes refreshes that timer during a long tool call, so the native watchdog saw recent activity throughout the wait. The bridge now advances LifeOS's activity clock only when the live child transcript gains a tool result line. Three focused regression tests passed, followed by the full `.212` plugin suite: 173 tests, 45 optional skips. The second clock fix is installed and the gateway restarted. An actual alert after this fix remains unverified.
