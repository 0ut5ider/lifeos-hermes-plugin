# Redirect targets bypass bridge file rules

Date: 2026-09-28. Claude Code 2.1.272 ran in the isolated `.212` reference account through the private local model. The prompt requested one Bash call, `printf PARITY > parity-probe.txt`, in the reference account's `.claude` directory. With `Bash(printf PARITY > parity-probe.txt)` allowed and no file rule, Claude reported zero permission denials and created the disposable file. With the same Bash allow plus `Edit(./parity-probe.txt)` denied, it reported one permission denial and created no file. The probe removed the file afterward.

The plugin's `HookBridge.command_approval` received the same command and rules in a disposable local root. A synthetic native `PermissionRequest` hook granted the command. The bridge returned `{"action":"allow"}` despite the `Edit` deny. Its Bash rule decision inspects only `Bash(...)` entries; it does not inspect the redirect target or file rules. This is a measured authorization difference, not just an extra approval prompt. The official [Claude Code permissions guide](https://code.claude.com/docs/en/permissions#redirections) says output redirects check `Edit` rules and input redirects check `Read` rules. It also checks recognized `tee` output targets.

The first reference attempts failed for test setup reasons. Invoking the raw Claude binary skipped the private gateway settings and returned an authentication error. Invoking its local gateway launcher without `--effort medium` returned HTTP 400 because the gateway does not accept `high`. A shell fed to `bash -s` also let Claude consume the remaining script from standard input; redirecting Claude's input from `/dev/null` allowed later probe checks to run. None of those failures established permission behavior. The paired runs above did.

Next, retain each permission source's path when loading settings, parse redirect and `tee` targets, and apply the appropriate file-rule precedence before a native hook grant can approve the Bash call. Relative, home-relative, source-anchored, and absolute patterns have different anchors. Remote workspaces and symlink paths need separate verification. Until that evaluator exists, a granted native hook can override a Claude file-rule deny in Hermes.
