# Worker recovery boundaries

The frozen Python 3.14.7 runtime rejects `os.posix_spawn(..., setsid=True)` with `NotImplementedError`. The earlier interpreter used during development accepts that option. Three complete synthetic installations reach their intended interruption boundaries, then fail at the detached recovery launch. The portable launch uses `subprocess.Popen(start_new_session=True)` and retains the process in a wait thread. An actual process test checks the session, process receipt, exit, and clean resource-warning output. The rebuilt f6e83998 package passes all three complete interruption cases and preserves later synthetic user data.

The existing native mount fix migrates schema 46 to 50 before recording mount hashes. That leaves another window before native mounting: the program transaction publishes a generated schema-46 configuration beside the new Hermes launcher. A private copy of the actual prepared configuration changes from SHA256 4721780fdd54fe4ada537cfeafe7c6c7578d8aa64220ce66a5bc29a38c7db377 to 48e26beedf2d0630890ba08419d52abc2b03062ae46b42e778c42316a58b2c31 when the assembled native launcher starts. Only the schema version changes semantically; the model remains unchanged.

The program preparation step now invokes the candidate's official migration and configuration check before the program transaction records its expected bytes. The regression starts the actual native configuration checker again and requires byte-for-byte stability. A source-only invocation of `hermes_cli.main` does not perform assembled boot maintenance, so the preparation step must call `step_migrate_config` explicitly. Qualification of the superseding complete package remains required.
