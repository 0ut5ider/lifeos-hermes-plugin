# Claude Code Bash permission reference probe

Date: 2026-09-28. The isolated Claude Code reference account on `.212` used the private LAN model. A disposable settings file registered `PreToolUse` and `PermissionRequest` Bash hooks. The permission hook denied every request so no probed command with a permission prompt executed.

The first one-shot probe produced Bash calls but no hook log entries. Claude's debug file reported `EACCES: permission denied, posix_spawn '/bin/sh'` for both hooks. The test process started in `/home/outsider`, which the isolated reference account could not traverse. Running it from that account's own `~/.claude` directory fixed the hook launch. The earlier claim that this reference setup did not deliver Bash events was incorrect.

With the working directory corrected, `echo 67890` invoked `PreToolUse` and executed without `PermissionRequest`. `echo 67890; echo "exit=$?"` invoked both hooks; the synthetic permission hook denied it and the tool reported `Permission denied by hook`. `curl -I http://192.168.8.1:9` also invoked both hooks and was denied before execution. These observations come from Claude Code 2.1.272 in the disposable account and do not define every trigger rule for other versions or commands.

For the same three commands, Hermes's dangerous command detector returned false. The installed native LifeOS `Safety.hook.ts` returned allow for the two echo commands and neutral for the LAN curl. Hermes previously ran its command policy plugin only for detected dangerous commands, so it would autoapprove the neutral curl. The new generic command policy host patch invokes the plugin for every command that reaches the normal guard, including isolated Docker commands. Neutral LifeOS `PermissionRequest:Bash` decisions ask for human approval. The integration test checks these outcomes with a disposable LifeOS state directory; it does not execute curl.
