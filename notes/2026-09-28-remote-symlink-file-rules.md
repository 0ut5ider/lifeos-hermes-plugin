# Remote symlinks and file permission rules

Date: 2026-09-28. Claude Code 2.1.272 ran in the isolated `.212` reference account through its private local model. A disposable project contained `link.txt` pointing to a file outside the project. With `Bash(cat link.txt)` allowed, the command returned the synthetic marker and reported no permission denials. Adding a `Read(//...)` deny for the resolved destination produced one denial and no marker. The probe used `--settings` and the default permission mode. An earlier run with `dontAsk` denied both variants, so it did not establish symlink behavior.

The bridge applied the deny to a host path but treated the same target as allowed when `host_paths=False`. The remote evaluator did not resolve symlinks. A regression captured this difference before the fix. The bridge now asks the owning backend for a physical path before it applies file rules. It checks the requested and resolved paths. If the backend cannot resolve a path, a Bash allow cannot grant it automatically, and a direct file tool requests human review. The path is shell quoted, and malformed backend output also requests review.

A live SSH test on `.212` passed for both a Bash `cat` call and a direct Read call. Its ordinary-file control remained allowed. The first SSH test used a deny rule with `project/../secret` while the backend returned the normalized absolute path. That test returned review because the rule spelling did not match; normalizing the test rule made the denial pass.

A live Docker test on `.212` initially denied Bash but requested review for direct Read. Instrumentation showed that the direct tool's working directory fell back to the host plugin checkout because no session directory was recorded in this isolated test. The remote resolver could not start in that directory. The bridge now uses the active backend's working directory when Hermes has no authoritative session directory. The Docker Bash and direct Read denials then passed. The temporary Docker socket access control entry for `lifeos-hermes` was removed after each test.

The local suite passed 276 tests with 66 optional skips. The `.212` source suite passed 276 tests with 55 optional skips. One local full-suite run observed an empty asynchronous hook marker; that test passed alone and the next full run passed. No asynchronous hook code changed. Physical path checks can race with filesystem changes between approval and execution, as host `realpath` checks can. SSH and Docker were live tested; other remote backend types and path rule forms remain unverified.
