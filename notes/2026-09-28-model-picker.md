# Configured Hermes models in LifeOS tier settings

Date: 2026-09-28. Adrian found the nine-field LifeOS Bridge form confusing. Its model inputs accepted free text, so a user had to know provider model IDs and could not see which models Hermes had configured. The form now reads Hermes's authenticated `/api/model/options?explicit_only=1` catalog and shows four rows. Each row saves a provider, model, and effort. The pinned tier is under Advanced.

The first provider-aware design exposed a routing gap. Hermes delegated children inherited the parent's endpoint even when the plugin selected a different model name. The new delegation patch resolves each task's selected provider credentials and endpoint. The LifeOS child launcher uses Hermes's managed Python and auxiliary client when the tier selects a provider. A live `.212` request through the installed `custom` provider returned `READY` as `flashnext-w4a16-fp8ple`. Its recorded output token count was 36 on the first call and 24 on the installed-path call. The local gateway is the only configured provider in this test account, so a live cross-provider call remains unverified.

Hermes's auxiliary client can fall back to another provider on a capacity or connection failure, even when the caller names a provider. That behavior conflicts with this deployment's private-routing expectation. The direct provider patch adds `allow_provider_fallback=False`. A local endpoint returning HTTP 503 exercised the recovery path and verified that the provider-fallback rung was not called. This flag applies to the LifeOS direct child call. Hermes agent delegation has its own fallback policy and needs separate route-policy verification before promising the same fail-closed behavior there.

The selected-provider child route no longer needs a separate `model.env` token or `LIFEOS_CHILD_INFERENCE_DIRECT` switch. An unselected tier keeps the existing LifeOS child default. The dashboard is installed on `.212`; visual inspection of the revised layout remains pending because the collaborative browser was unavailable in the headless environment.
