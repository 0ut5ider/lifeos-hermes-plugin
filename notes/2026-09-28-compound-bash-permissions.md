# Compound Bash permission probe

Date: 2026-09-28. Claude Code 2.1.272 ran in the isolated `.212` reference account through the private LAN model. A disposable settings file denied `Bash(printf world)` and logged Bash `PreToolUse` and `PermissionRequest` events. The model called Bash once with `printf hello; printf world`. The log held one `PreToolUse` event and no `PermissionRequest` event; Claude reported that permission denied the compound command. Neither `printf` executed. The probe directory was removed after the run.

Before the parser change, the Hermes bridge returned no verdict for that same command and rule. The bridge compared the rule with the whole command string, so it missed the second subcommand. A bridge regression failed with `None != {'action': 'deny'}`. The [Claude Code permission reference](https://code.claude.com/docs/en/permissions#compound-commands) says deny and ask rules match any parsed subcommand, including commands in substitutions and control-flow bodies, while allow rules must cover each subcommand. It also lists wrappers that Claude strips before matching.

An official `tree-sitter-bash` wheel installed with `tree-sitter` in a disposable Python 3.14 virtual environment. The parser identified the two `command` nodes, a nested `command_substitution`, a `for_statement` body, and the argument of `timeout`. Hermes validated a staged plugin manifest with the two exact Python dependencies and passed its isolated capability probe. The bridge now uses the parsed command nodes for rule matching. It keeps redirects on the review path for allows because Claude also checks protected file paths there. Other shell forms still need live reference and installed Hermes probes before full Bash parity can be claimed.
