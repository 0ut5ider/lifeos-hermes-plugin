# Knowledge lint still needs caller authority

The broad memory regression passes 1,428 cases, but the next caller audit finds an unguarded diagnostic. A synthetic Knowledge archive contains two registered notes. Running the original KnowledgeLint with a connector and no caller context exits zero. It reports both private filenames and the count of two notes. Its native schema checks pass their characterization comparisons, which says nothing about caller admission.

The correction keeps the native validator and report strings. A governed service supplies current registered notes and checks authority after the render. Nine focused cases pass, including seven comparisons with the pinned original report. A subprocess observer lets the actual renderer finish before changing source metadata or the account grant. Both changes withhold the report. Unknown and forgotten notes no longer contribute labels or counts.

The useful distinction is between validating archive structure and authorizing a diagnostic about that archive. A read-only diagnostic can disclose file names, relation labels, and aggregate counts. Its source and response boundaries need the same caller checks as ordinary recall. Canonical validation can refuse excluded or malformed source metadata before the linter runs. That refusal remains explicit; it does not establish native report equality for refused data.
