# Reviewed release on the .212 test server

Date: 2026-09-29
Target: `lifeos-hermes` on `192.168.8.212`

The reviewed patch footprint branch was merged into `main` at `e762ac6` and pushed to GitHub. The active server has an older bridge, Hermes commit `9a8942c`, and LifeOS commit `af60000`. Its `.claude` path links to the shared `.hermes` home. This release preserves that layout. The newer separate-root updater cannot apply to it directly.

The live VersionDrift baseline reports zero changes. The hook ownership check finds all 74 native registrations and no foreign registrations. The selected LifeOS payload has no package or dependency lock changes. Six source-backed files change: TaskGovernance, EventLogger, CheckpointPerISC, ModelRungGuard, the capability record, and IntegrityCheck. The release must preserve generated identity files and existing user data.

Release inspection found an installer integration error that the earlier review missed. The dashboard loads `install_source.py` as a standalone module. Its new relative capability import then raises `ImportError: attempted relative import with no known parent package`. The regression test uses the dashboard's loader and a real Git source candidate. It fails before the fix and passes afterward. Source preparation now loads the adjacent standard-library-only capability module through `runpy`, so both loading contexts use the same implementation and record.

The corrected local plugin suite passes 348 cases, with 51 environment-dependent skips (399 total). The installer subset passes all 10 cases. Deployment verification and recovery evidence will be added after the server transaction completes. The `.211` and `.213` installations are outside this release.

The first release attempt stopped before any code change. Pulse created `LIFEOS/PULSE/state/state.json` during shutdown. The drift scanner treated this runtime file as a new system file. The worker restarted the original services. Two regression tests reproduced the false drift and verified that a Pulse source edit still counts. The scanner now excludes only the Pulse runtime state directory from baseline files and drift results. Both tests pass after the fix. This release retries with the corrected plugin revision.

The second attempt rolled back after cache invalidation found two directories owned by root: `acp_adapter/__pycache__` and `agent/vault_backends/__pycache__`. The worker restored the original code and restarted all three services. Inspection found three incorrectly owned entries in the first cache and four in the second. The operator changed ownership of those cache entries to `lifeos-hermes`. The retry keeps the rollback snapshot and failure log in a separate private attempt directory. Each retry uses a distinct local release branch.

The extended model check exposed a source integration regression. The turn gate forwards `provider` to `get_pre_turn_stop_continue_message`, but the dispatcher did not accept that argument. It raised `TypeError`, so Hermes failed the answer with `stop_gate_blocked`. The model reached the requested private route at xhigh effort. Changing the prompt and iteration budget did not change the exception. The correction adds and forwards the provider argument in the generic plugin event patch. A regression test calls the real dispatcher from the turn gate and observes the plugin event. It fails before the correction and passes afterward. The earlier provider test replaced the dispatcher and missed this error.

```sh

It saves divergent managed native files before restoration. Automatic recovery ran successfully during the failed attempts. The explicit restore action has not been run after the successful release.
