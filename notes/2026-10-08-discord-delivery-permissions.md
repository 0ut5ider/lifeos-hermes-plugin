# Discord audience changes at delivery

Date: 2026-10-08. The daily text release requires one private channel for Adrian and Shiny Hermes Bot.

An actual Discord SDK fixture posts a generated response after another member receives channel access. Configuration and channel identifiers do not change. Five initial controls fail, and the unchanged delivery control proves a real authenticated HTTP post.

The release candidate reads the audience before every private post or edit. The policy callback receives identifiers and profile binding, but no message content or credential. The host compares the transport credential with its current profile credential separately. Missing, unknown, failed, or late policy results cannot permit a write.

A further experiment finds that oversized final edits report success after permission denial stops their remaining chunks. The transport now reports failure while retaining the count of chunks already delivered. Native network failure behavior remains covered separately.

Timeout card edits and attachment paths also bypass the ordinary response sender. Their controls use actual SDK objects and authenticated local HTTP requests. The guard follows those writes too. This does not remove content already posted before someone changes Discord permissions, and it does not make the permission read atomic with Discord delivery.
