# SessionEnd reason mapping and resume boundaries

Date: 2026-09-28. Target: the pinned Claude Code 2.1.272 reference and the `.212` Hermes test install.

[Claude's SessionEnd reference](https://code.claude.com/docs/en/hooks#sessionend) defines `clear`, `resume`, `logout`, `prompt_input_exit`, and `other`. It says an interactive `/resume` ends the previous session with reason `resume`. The bridge was registered on Hermes `on_session_finalize`, so it already ran at a true session boundary. It discarded the supplied Hermes reason and always passed `other` to LifeOS. The `.212` gateway and CLI also switched sessions on `/resume` without emitting `on_session_finalize`. These observations narrowed the issue from a suspected event-cadence problem to missing reason propagation and missing resume finalization.

The bridge now maps Hermes `new_session` to Claude `clear`, passes `resume`, `logout`, and `prompt_input_exit`, and maps unrecognized reasons to `other`. The new generic Hermes patch emits `on_session_finalize` after a successful gateway `/resume` switch and before clearing conversation state. The CLI emits it before replacing the current session ID. It passes `resume` through its existing lifecycle helper.

The regression failed before each code change. The bridge test observed three `other` reasons instead of `clear`, `resume`, and `other`. The gateway test observed zero finalization calls. The CLI test observed zero finalization calls. After the changes, the bridge reason tests passed, the focused Hermes gateway and CLI suite passed 54 tests, and all 13 Hermes patches applied to the pinned base in a fresh prepared source tree. The full `.212` plugin suite passed 302 tests, with 55 optional skips. The installed `.212` plugin file was backed up as `bridge.py.before-session-reasons-20260928`, replaced with the tested bridge source, and the gateway service restarted.

The gateway patch deliberately finalizes only after the session switch succeeds. A failed switch leaves the current session intact. The `.212` test virtual environment needed `pytest-asyncio` to run existing async gateway tests; it was installed there, not in the Hermes runtime.

A pinned Claude Code interactive probe then produced `clear`, `resume`, and `prompt_input_exit` for `/clear`, `/resume`, and exit at the prompt. The raw event sequence is in `docs/agents/2026-09-28-session-end-control/results.json`. The first Hermes PTY probe appeared idle because its input handler treats Enter within 50 ms of a text change as a pasted newline. Delaying Enter by 250 ms submitted `/exit` and exposed a real mismatch: the installed plugin received `other` with a null session ID. A generic Hermes CLI patch now passes `prompt_input_exit` for a normal prompt exit and retains the CLI session ID even if no agent turn ran. Two regressions failed before the change. Afterward, 35 focused Hermes cleanup tests passed and a real `.212` interactive CLI `/exit` delivered `prompt_input_exit` with session ID `20260928_203614_557d2e`. A prompt exit after a completed model turn and native-equivalent Hermes `/clear` and `/resume` sequences still require paired live runs.

Claude Code also emitted `clear` when `/clear` was the first interactive command in a fresh session. Hermes's matching empty-session `/new` emitted no SessionEnd event. The CLI only finalized when an agent object existed and used `session_boundary` as the reason. The generic patch now finalizes the old session ID regardless of agent creation and sends `new_session`, which the bridge maps to `clear`. Both new source regressions failed before the change; 51 focused host tests passed afterward. A real `.212` CLI `/new` emitted `clear` for the old session. The probe's following `/exit` stayed in the prompt without dispatching, so that two-command sequence is not yet a complete paired outcome. The separate `/exit` probe above did complete.
